## 1. 产品概述

### 1.1 产品背景

用户有日常情绪表达需求，但在熟人社交平台发帖会承受身份暴露压力；专业咨询又存在费用、预约和心理门槛。很多用户只想表达几句、确认有人看见，并获得轻量回应。

### 1.2 产品定位

JIJU 是微信小程序中的公共情绪表达空间。用户无需经营个人身份，也不需要建立社交关系，即可以发布带有情绪标签和情境标签的文字帖子；其他用户可以评论，或通过固定轻互动表达善意。

平台提供表达空间、基础内容治理和危机资源提示，不提供心理咨询、治疗、诊断或危机干预。

### 1.3 待验证假设

1. 用户是否愿意在公共、无熟人关系的空间中表达情绪。
2. 用户是否愿意通过评论或轻互动回应陌生人。
3. 轻互动能否降低回应门槛，并让发布者感到被看见。

### 1.4 产品目标与衡量方式

MVP 的首要衡量指标为“24 小时回应率”，用于验证有效帖子在发布后 24 小时内是否至少获得一次评论或轻互动。辅助指标用于观察登录摩擦、表达完成度、回访和治理成本。

MVP 先建立可信数据口径，再依据试点数据确定增长目标值。首期不得使用“治疗”“治愈”“危机干预”等效果承诺作为宣传或指标。

### 1.5 产品边界

本产品不提供以下能力，也不将其作为后续版本默认储备：

- 心理咨询、治疗、临床诊断和危机干预；
- 好友、关注、粉丝等用户关系链；
- 用户匹配、一对一私信或群聊；
- 帮助者准入、培训、评级及付费服务体系；
- 个人主页、用户内容聚合页或可点击的陌生人身份入口。

平台可以提供高风险表达的求助资源提示、举报和人工复核，但这些能力不构成专业服务承诺。

## 2. 用户与场景

### 2.1 表达者

当下有情绪，想说几句、希望被看见，但不愿在熟人圈表达，或暂时不需要专业咨询的普通用户。

典型场景：

- 深夜睡不着，想表达最近的疲惫；
- 下班路上，想说说工作中的委屈；
- 与家人或伴侣争吵后，想找个地方说几句；
- 独处时感到失落，希望获得一点回应。

### 2.2 回应者

看见他人帖子后愿意表达善意，但不一定擅长组织语言，或不想开展深入交流的用户。产品只提供评论和固定轻互动，不把互动扩展为关系建立工具。

### 2.3 游客

尚未登录、仅浏览公共内容的用户。游客可以低成本了解广场氛围，在表达或互动时才进入登录流程。

### 2.4 运营与审核人员

通过运营后台处理举报、复核高风险内容、执行内容下架和账号限制，并可审计处理过程。运营人员不能通过普通用户端获得额外身份展示能力。

## 3. 产品原则

1. **表达优先**：发布流程简单，不要求用户解释背景或提出明确诉求。
2. **低压力进入**：游客可以浏览；只在发布、评论、互动或查看个人内容时登录。
3. **不建立关系**：不提供个人主页、好友、关注、粉丝、匹配和私信。
4. **公开属性明确**：用户发布前必须知道内容会展示给广场用户，可能被查看或截图。
5. **允许真实情绪**：难过、焦虑、孤独等负面情绪本身不能作为违规依据。
6. **风险分级治理**：优先拦截明确危险或侵害内容；对不确定风险进入提示和人工复核，不把词命中等同于用户有危险。
7. **不作专业承诺**：不得将平台描述为咨询、治疗、诊断或紧急求助渠道。
8. **最小化身份**：不展示微信头像、昵称等资料，不建立可被追踪的社交身份。

## 4. MVP 范围

### 4.1 本期范围

| 模块 | MVP 内容 |
| --- | --- |
| 浏览 | 游客浏览广场信息流、帖子详情和评论；查看轻互动数量 |
| 账号 | 微信登录、生成广场昵称、使用须知确认、账号注销入口 |
| 发布 | 纯文字帖子、情绪标签、情境标签、留存时长、发布前确认 |
| 回应 | 评论、三种固定轻互动、评论删除、轻互动切换和取消 |
| 个人内容 | 查看有效和已到期帖子、浏览量、收到的评论与轻互动 |
| 治理 | 内容校验、举报、高风险提示、人工复核、下架和账号限制 |
| 数据 | 核心指标埋点、基础运行指标、审计日志 |

### 4.2 本期不纳入

- AI 对话或 AI 辅助生成、审核；
- 图片、语音、视频等多媒体内容；
- 个性化信息流、热门排序和推荐算法；
- 心理科普、心理测评、性格测评等工具；
- 好友、关注、私信、匹配、群组；
- 用户自定义互动、评论楼中楼、帖子收藏；
- 面向未成年人的独立模式、监护人或年龄验证流程。

“本期不纳入”不表示可以忽略未成年人保护、内容安全和隐私合规。相关义务由第 10 节和上线阻断项约束。

## 5. 全局规则

### 5.1 权限矩阵

| 操作 | 游客 | 已登录非作者 | 帖子作者 | 运营人员 |
| --- | --- | --- | --- | --- |
| 浏览有效帖子及评论 | 允许 | 允许 | 允许 | 允许 |
| 查看轻互动总数及分类数量 | 允许 | 允许 | 允许 | 允许 |
| 查看浏览量 | 禁止 | 禁止 | 允许 | 仅后台审计需要时允许 |
| 发布帖子 | 禁止 | 允许，受配额限制 | 允许，受配额限制 | 按普通账号规则处理 |
| 评论 | 禁止 | 允许，受配额限制 | 允许，受配额限制 | 按普通账号规则处理 |
| 发送、修改或取消轻互动 | 禁止 | 允许 | 允许 | 按普通账号规则处理 |
| 编辑或删除帖子 | 禁止 | 禁止 | 允许 | 只能在运营后台执行治理操作 |
| 删除自己的评论 | 禁止 | 允许 | 允许 | 只能在运营后台执行治理操作 |
| 举报内容 | 禁止 | 允许 | 允许 | 按普通账号规则处理 |
| 查看“我的” | 禁止 | 允许 | 允许 | 普通用户端无特殊入口 |

权限必须在服务端校验。客户端隐藏按钮不能替代接口鉴权；不得通过猜测 ID 查看他人浏览量、草稿或已删除内容。

### 5.2 登录与账号

- 发布、评论、发送轻互动、举报或进入“我的”时，需要完成微信登录。
- 发布页应当允许用户先编辑内容，在点击“发布”时再触发登录，避免过早打断表达。
- 登录成功后必须恢复登录前的页面、操作意图和已填写内容；用户取消登录时返回原页面并保留本地草稿。
- 本机草稿最多保留 24 小时，草稿只保存在用户设备；服务端不得在用户提交前收集草稿正文。
- 使用须知必须在用户首次进行表达或互动前展示；确认后方可继续。确认记录包含用户、协议版本和确认时间。
- 平台内部建立不可公开的账号标识，用于权限校验、频率限制和治理。
- 系统为账号生成稳定的广场昵称，例如“晚风 2841”。昵称不要求唯一，不展示微信头像或微信昵称，昵称不可点击进入主页。
- 提供账号注销入口。注销后的公开内容、互动记录、举报和审计数据如何删除或保留，须按隐私政策和适用要求执行。

### 5.3 时间与业务日

- 服务端使用统一时间源并以 UTC 存储时间。
- 用户界面按北京时间展示；“自然日”和“连续 60 分钟”均由服务端按北京时间计算。
- 帖子到期时间以发布成功时确定的 `expires_at` 为准，不因编辑、刷新或再次访问而延长。
- 到期边界统一采用 `server_now >= expires_at`。到期判断不能只依赖异步定时任务，查询时必须同时执行到期过滤。

### 5.4 文本处理规则

- 帖子正文提交前去除首尾空白；去除后不得为空。
- 帖子正文最多 500 个用户可见字符，评论最多 200 个用户可见字符。
- “字符”按 Unicode 扩展字素簇计数；组合 emoji 不能因编码长度差异造成前后端计数不一致。
- 超出上限时不得截断后静默发布，必须提示用户修改。
- 标签、昵称和评论不得通过 Unicode 控制字符、零宽字符等方式绕过内容校验。
- 内容校验以服务端结果为准。客户端校验仅用于减少无效请求。

### 5.5 幂等与并发

- 发布、评论、轻互动、编辑、删除和举报请求必须支持客户端请求 ID，或采用等价的服务端幂等机制。
- 用户重复点击或网络重试时，同一业务操作最多成功一次，不得重复生成内容、重复计数或重复消耗成功配额。
- 同一用户对同一帖子的轻互动并发请求完成后，最多保留一条有效互动。
- 分页刷新时不得因新内容插入而返回大量重复帖子；允许使用游标或等价机制。

### 5.6 帖子状态

为便于开发，帖子的公开状态与审核状态应分开管理：

- 公开状态：`DRAFT`（仅本地）、`PUBLISHED`、`HIDDEN`、`EXPIRED`、`DELETED`。
- 审核状态：`PASSED`、`PENDING`、`REJECTED`。

状态规则：

| 状态变化 | 允许条件 | 结果 |
| --- | --- | --- |
| 草稿到已发布 | 登录、须知已确认、内容校验通过、配额未满 | 生成帖子 ID 和固定 `expires_at` |
| 已发布到审核中 | 命中需人工复核但允许发布的风险规则，且用户确认风险提示 | 内容可继续展示，进入人工复核队列 |
| 已发布到隐藏 | 运营下架或达到治理规则 | 广场、详情均不可见，作者在“我的”看到已下架状态 |
| 已发布到到期 | 到达 `expires_at` | 公开区域不可见，作者可查看历史内容 |
| 任意公开状态到删除 | 作者主动删除 | 不再公开，作者不可通过“我的”查看 |

审核中内容若被判定为明确违规，必须立即转为隐藏。审核状态不得被客户端修改。

### 5.7 编辑与版本

- 作者只能编辑自己的有效帖子，已到期、已删除或被禁止编辑的帖子不可编辑。
- 编辑不得改变帖子 ID、发布时间和 `expires_at`。
- 编辑提交后先执行内容校验；校验未通过时不得替换当前公开版本。
- 校验通过后保存新版本并更新展示内容，同时记录编辑时间和版本。高风险编辑仍需风险确认，并重新进入人工复核。
- 举报和审核记录应关联到被举报时的内容版本，避免用户编辑后掩盖原内容。
- MVP 评论不支持编辑，只支持作者删除。

### 5.8 标签快照

- 标签由服务端配置，具有稳定 ID、名称、排序和启用状态。
- 运营可新增、停用或重命名标签；停用后不能用于新帖子，历史帖子保留发布时的标签名称和 ID。
- “其他”是固定选项，不提供自由文本补充字段。

### 5.9 用户可见错误

- 内容过期、被删除或不可见时，统一展示“内容已不可用”，不得泄露内容是否存在。
- 权限不足、登录失效、内容校验失败、达到配额、网络失败必须区分提示。
- 对失败请求提供明确下一步；可重试操作应保留用户输入。

## 6. 信息架构

微信小程序底部导航包含：

1. **广场**：浏览公共帖子。
2. **发布**：创建情绪帖子。
3. **我的**：查看自己的帖子、回应和账号相关信息。

其他页面：

- 帖子详情：正文、评论、轻互动、举报入口。
- 使用须知：首次表达或互动前展示。
- 协议与隐私：用户协议、隐私政策、内容规范和账号注销。
- 运营后台：独立入口，至少要求后台身份认证和角色权限。

## 7. 核心流程

### 7.1 浏览

打开小程序 → 进入广场 → 浏览帖子 → 下拉刷新或加载更多 → 打开详情 → 查看评论和轻互动。

帖子在列表停留期间已到期或被下架时，打开详情应提示“内容已不可用”，并允许返回刷新列表。

### 7.2 发布

进入发布页 → 输入正文 → 选择情绪标签 → 选择情境标签 → 选择留存时长 → 点击发布 → 按需登录 → 按需确认使用须知 → 展示公开属性提示 → 内容校验 → 配额校验 → 发布成功 → 进入帖子详情。

异常分支：

- 登录失败或取消：保留草稿，返回发布页。
- 正文字数超限或为空：定位并提示具体字段。
- 内容明确违规：阻止发布，不消耗成功配额，保留可修改内容。
- 内容需要风险复核：展示风险提示和求助资源；用户取消则保留内容，用户确认后按规则发布。
- 发帖配额已满：阻止发布，展示解除时间和剩余等待时间。
- 网络超时或重复点击：使用幂等请求避免重复帖子。

### 7.3 评论

打开帖子 → 输入评论 → 点击提交 → 按需登录 → 内容校验 → 评论配额校验 → 提交成功 → 更新评论列表和评论数。

登录恢复后应回到原帖子和评论输入状态。达到配额时，应在输入框附近展示限制信息和解除时间。

### 7.4 轻互动

打开帖子 → 选择一种轻互动 → 按需登录 → 提交成功 → 更新数量和当前选择。

已选择过的用户可以切换到另一互动，也可以取消当前互动。任何时刻每位用户对同一帖子最多保留一种轻互动。

### 7.5 查看回应

进入“我的” → 查看有效或已到期帖子 → 查看浏览量、评论数、轻互动数 → 打开帖子 → 查看具体评论和互动分类数量。

轻互动不展示参与者身份；评论展示评论者广场昵称和评论时间。

### 7.6 到期、删除和治理

- 到期：帖子自动从公开区域移除，禁止新增评论和轻互动，作者仍可查看历史内容。
- 主动删除：帖子立即从公开区域移除，作者不可在“我的”查看。
- 治理下架：内容从公开区域移除，作者看到“已下架”；治理人员可在后台查看内容版本和处理记录。

## 8. 功能需求

### 8.1 账号与访问控制

| ID | 需求 |
| --- | --- |
| AUTH-01 | 发布、评论、轻互动、举报和查看个人内容时，服务端必须验证登录状态。 |
| AUTH-02 | 登录成功后恢复登录前的页面、操作意图和已填写内容；取消登录时保留本地草稿。 |
| AUTH-03 | 用户首次表达或互动前展示当前版本使用须知；确认后才能继续，并记录用户、版本和时间。 |
| AUTH-04 | 系统为账号生成稳定广场昵称，不展示微信头像和微信昵称，昵称不可进入个人主页。 |
| AUTH-05 | 登录态失效时提示重新登录；不得将权限错误伪装成内容不存在。 |
| AUTH-06 | 提供账号注销入口和相关协议入口；注销后的数据处理遵循隐私政策。 |

## 9. 内容安全与风险表达

### 9.1 校验范围

内容校验对象包括帖子正文、评论、举报“其他”说明和必要的运营备注。校验范围覆盖：

- 辱骂、攻击、威胁或骚扰；
- 个人隐私和联系方式；
- 广告及垃圾信息；
- 危险内容和不适当内容；
- 高频提交等疑似滥用行为；
- 涉及未成年人身份、隐私或性相关的内容。

### 9.2 校验结果

| 结果 | 用户处理 | 内容状态 |
| --- | --- | --- |
| 通过 | 正常发布 | 已发布、审核通过 |
| 需确认 | 展示风险说明和经核实的外部求助资源；用户确认后可发布 | 已发布、待人工复核 |
| 阻断 | 阻止发布，提示修改；不消耗成功配额 | 不生成公开内容 |

规则命中不等于用户处于危机。不得在文案中宣称平台能够识别或处理所有风险情况。

### 9.3 高风险文案

命中高风险规则时，发布页必须说明：

- 平台不提供心理咨询、治疗或危机干预；
- 平台不是紧急求助渠道；
- 如存在即时人身危险，应联系当地紧急服务或可信任的人；
- 外部求助资源的名称、适用范围和更新时间。

外部资源链接须验证在小程序内可打开；若平台限制外链，必须提供可复制的信息或其他可用路径。

### 9.4 未成年人保护

当前方案：MVP 不主动采集年龄，不进行人脸识别或身份验证，不对外宣称仅面向成年人，也不在文案中承诺已具备完整的未成年人保护能力。

实现规则：

- 不在使用须知或账号资料中要求用户自行填写年龄；未采集的年龄不得用于判断服务资格。
- 自伤方法、细节、鼓励伤害等内容对所有用户一律不进入公域。
- 自述为未成年人、出现校园语料、深夜高频使用等信号只能作为风险标记，不得单独据此封号。
- 涉及未成年人的举报必须单独标记和优先人工处理。
- 帖子到期后从公域隐去，降低长期留痕及后续扩散风险。

**合规阻断项**：默认向未成年人开放服务可能涉及未成年人模式、监护人同意、身份核验或其他法定义务。上线前必须由法务确认 MVP 的服务对象、准入方式和文案；在获得书面确认前，不得对外宣称平台“符合未成年人保护要求”或“已具备未成年人保护能力”。

## 10. 数据指标与埋点

### 10.1 核心指标

**24 小时回应率** = 在发布后 24 小时内至少获得一次评论或轻互动的有效帖子数 ÷ 24 小时观察期已经结束的有效帖子数。

口径要求：

- 有效帖子指成功发布且未被判定为违规内容或测试数据的帖子。
- 一条帖子在一段观察窗口中最多计一次，评论和轻互动同时出现不重复计数。
- 用户主动删除或内容下架是否进入分子、分母，应在数据分析规则中统一记录；不得在不同报表中使用不同口径。
- 统计时间使用服务端时间，以北京时间展示。

### 10.2 辅助指标

- 游客广场浏览人数；
- 游客进入帖子详情的比例；
- 游客尝试互动后的登录转化率；
- 登录后恢复并完成原操作的比例；
- 发帖成功率；
- 帖子获得首次回应的时间；
- 轻互动和评论的使用比例；
- 发布者回访率；
- 发帖、评论频率上限触发次数；
- 举报率、违规下架率和误拦截反馈；
- 使用须知确认通过率；
- 高风险提示展示与内容修改率。

### 10.3 埋点事件

至少记录以下事件：

| 事件 | 关键属性 |
| --- | --- |
| `feed_view` | 来源、页码或游标、是否登录 |
| `post_detail_view` | 帖子 ID、入口、是否作者 |
| `create_post_click` | 是否登录 |
| `login_start` | 原操作类型 |
| `login_success` | 原操作类型、耗时 |
| `notice_confirm_view` | 协议版本 |
| `notice_confirm_pass` | 协议版本 |
| `post_publish_blocked` | 阻断类型、是否达配额，不记录正文 |
| `post_publish_success` | 帖子 ID、标签 ID、留存时长 |
| `comment_submit` | 帖子 ID、结果类型 |
| `comment_limit_reached` | 帖子 ID、解除时间 |
| `reaction_submit` | 帖子 ID、互动类型、动作 |
| `report_submit` | 对象类型、原因分类、是否未成年人标记 |
| `post_edit` | 帖子 ID、结果类型 |

所有埋点不得记录帖子正文、评论正文、举报说明、微信标识、手机号、身份证件号码或其他敏感个人信息。`openid`、IP 地址等内部标识不得作为常规分析 SDK 属性暴露。

### 11.4 可用性与无障碍

- 加载中、成功、失败和禁用状态必须有文字提示，不仅依赖颜色差异。
- 主要按钮和可点击区域应符合微信小程序交互规范，并避免过小触控区域。
- 发布、评论和举报的验证错误应定位到对应字段。
- 页面文案避免专业诊断、治疗承诺或制造羞耻感。

## 12. 验收标准

以下场景必须通过功能测试、接口鉴权测试和相应自动化测试：

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-01 | 用户未登录 | 打开广场和详情 | 可以浏览，不能发布、评论、互动、举报或查看“我的” |
| AC-02 | 游客已填写帖子并触发登录 | 完成登录 | 返回发布页，正文、标签和留存时长不丢失 |
| AC-03 | 用户已登录且须知已确认 | 发布合法帖子 | 在广场和详情可见，固定生成到期时间，返回详情 |
| AC-04 | 帖子正文为 501 个可见字符 | 提交发布 | 阻止发布，展示字数提示，不消耗成功配额 |
| AC-05 | 内容命中明确违规规则 | 提交 | 阻止发布，返回可修改提示，不产生公开内容 |
| AC-06 | 内容命中需复核规则 | 用户确认风险提示 | 内容进入人工复核，后台可查询并处理 |
| AC-07 | 用户当日成功发帖已 5 篇 | 再次发布 | 阻止发布，展示北京时间下一次可发布时间 |
| AC-08 | 用户对帖子尚未互动 | 发送轻互动 | 对应数量加一，其他两种不增加 |
| AC-09 | 用户已选择一种轻互动 | 切换到另一种 | 原数量减一，新数量加一，总数不变 |
| AC-10 | 用户已选择轻互动 | 取消互动 | 对应数量减一，不出现负数 |
| AC-11 | 用户在 60 分钟内成功评论 10 条 | 第 11 条提交 | 阻止提交，展示解除时间，不创建评论 |
| AC-12 | 同一用户、对象和原因 24 小时内重复举报 | 再次提交 | 返回已提交状态，不生成重复有效举报 |
| AC-13 | 浏览量已存在 | 非作者查看详情 | 前端不展示且接口不能返回浏览量 |
| AC-14 | 作者和其他用户分别打开详情 | 完成访问 | 浏览量只对作者展示，作者访问不计入 |
| AC-15 | 到达帖子 `expires_at` | 刷新广场、详情并尝试评论或互动 | 公开内容不可见，评论和互动均被服务端拒绝，作者仍可在“我的—已到期”查看 |
| AC-16 | 作者编辑有效帖子 | 新内容通过校验 | 更新正文和版本，到期时间不变，历史版本可供治理审计 |
| AC-17 | 作者编辑有效帖子 | 新内容校验失败 | 原公开版本不被替换，提示修改 |
| AC-18 | 作者删除有效帖子 | 返回“我的” | 帖子不再公开，作者也不能查看 |
| AC-19 | 举报包含“涉及未成年人” | 提交成功 | 后台单独标记并进入优先队列 |
| AC-20 | 客户端重复提交同一请求 | 发生重试 | 最多成功一次，不重复计数或消耗配额 |
| AC-21 | 游客尝试通过接口直接发布或评论 | 调用接口 | 服务端返回未登录或权限错误，不产生数据 |
| AC-22 | 使用须知尚未确认 | 用户尝试首次表达或互动 | 展示须知；确认前不能继续 |
| AC-23 | 内容已到期或下架 | 使用旧详情链接访问 | 统一提示内容不可用，不泄露作者权限或浏览量 |
| AC-24 | 达到性能基线测试条件 | 执行压测 | 首屏、详情和写入接口满足第 11.1 节 P95 目标 |
