## 1. 产品定义

### 1.1 一句话定位

JIJU 是一个无关注、无私信、无个人主页、无熟人关系链的公共情绪表达空间。用户可以匿名化地发布文字情绪、查看他人内容、发布评论并使用固定轻互动表达回应。

### 1.2 产品目标

1. 降低陌生人表达情绪时的身份压力。
2. 让用户只需少量输入即可完成一次表达。
3. 通过评论和固定轻互动提供低压力回应。
4. 对公共内容提供可追溯的审核、举报、处置和审计能力。

### 1.3 当前产品边界

当前系统不提供：

- 好友、关注、粉丝、私信、匹配、群组；
- 可点击的陌生人个人主页或用户内容聚合页；
- 微信头像、微信昵称、微信好友关系展示；
- 图片、语音、视频等多媒体帖子；
- AI 对话、AI 生成、AI 自动裁决；
- 帖子收藏、楼中楼评论、自定义互动；
- 心理咨询、诊断、治疗或危机干预承诺。

### 1.4 身份模型

- 用户身份由微信登录 code 换取，平台不公开微信身份信息。
- 广场使用平台昵称，不使用微信昵称和头像。
- 头像是系统生成的固定视觉元素，取昵称首字，不支持上传、配色或社交化编辑。
- 个人资料仅包含昵称，不包含个人简介。

## 2. 技术基线

| 层级 | 技术基线 |
| --- | --- |
| 小程序 | 微信小程序原生框架 + TypeScript |
| 后端 | Node.js 22+、NestJS 11 |
| 数据访问 | Prisma 6 |
| 数据库 | PostgreSQL |
| 缓存/短时状态 | Redis，通过 ioredis 接入 |
| 运营后台 | 由 NestJS 服务直接提供 HTML 管理界面 |
| 测试 | 小程序 Vitest；后端 Jest；OpenAPI、权限、任务包和 AC 文档校验脚本 |
| 时间 | 数据库和服务端使用 UTC；用户界面按北京时间展示 |
| 本地联调 | 微信开发工具关闭合法域名校验，通过局域网 HTTP 地址访问后端 |
| 正式上线 | 必须改为已备案并加入微信合法域名的 HTTPS API 地址 |

运营后台和小程序共用同一套业务 API，但后台使用独立用户名密码登录、独立会话和后台角色授权。

## 3. 用户角色

| 角色 | 定义 | 主要能力 |
| --- | --- | --- |
| 游客 | 没有有效用户登录态 | 浏览广场、详情、评论和互动数量 |
| 登录用户 | 有有效普通用户会话 | 发布、评论、互动、举报、查看本人内容 |
| 作者 | 当前帖子或评论的创建者 | 在普通用户规则外，可编辑或删除本人内容、查看本人帖子浏览量 |
| 运营人员 | 独立后台身份 + 后台角色 | 查看举报、复核、内容治理、用户处置和审计 |

后台角色包括：

- `REPORT_REVIEWER`
- `CONTENT_MODERATOR`
- `ACCOUNT_MODERATOR`
- `AUDITOR`
- `CONFIG_ADMIN`

权限最终以服务端校验为准，客户端隐藏按钮不构成授权。

## 5. 登录、须知与会话

### 5.1 登录前须知

- 登录页展示“我已阅读并同意《使用须知》”勾选框。
- 未勾选时不能发起微信登录。
- 使用须知支持登录前只读查看。
- 登录成功后，客户端调用服务端确认当前须知版本。
- 已有有效登录且当前须知已确认时，可直接返回原页面。
- 首次发布、评论、互动或举报前，服务端仍校验当前须知确认状态。

### 5.2 登录流程

1. 用户从发布、详情、举报、“我的”等入口进入独立登录页。
2. 阅读并勾选使用须知。
3. 微信小程序调用 `wx.login` 获取临时 code。
4. 服务端通过微信 provider 换取内部身份。
5. 平台创建或定位用户并返回访问令牌、到期时间、昵称、须知版本。
6. 登录页确认须知后返回原页面。
7. 原页面保留草稿、评论输入和操作意图。

### 5.3 会话规则

- 普通用户会话默认有效期由服务端返回。
- 客户端只保存平台访问令牌，不保存微信 openid、unionid 或 session_key。
- 本地会话在过期、损坏或缺少必要字段时自动清除。
- 退出登录只撤销当前会话，不删除账号和内容。
- 退出登录后返回情绪广场首页。
- 账号处于注销冷静期且仍可恢复时，登录页可提示恢复账号。

### 5.4 微信登录实现状态

- 非生产环境可使用 mock 微信 provider。
- 生产环境禁止 mock。
- 正式微信 code2Session 适配器已存在，但真实 AppID、AppSecret、真机授权和生产换码仍属于上线联调项。
- 服务端不得在响应或日志中返回 openid、unionid、session_key。

## 6. 情绪广场

### 6.1 列表范围

- 只展示同时满足公开可见条件的有效帖子。
- 到期、隐藏、删除或不满足审核公开条件的帖子不进入广场。
- 游客可浏览。

### 6.2 卡片内容

每张卡片展示：

- 作者广场昵称
- 发布时间
- 正文摘要
- 情绪标签快照
- 情境标签快照
- 评论数
- 轻互动总数

广场卡片不展示浏览量。

### 6.3 长文本

- 服务端最多返回 120 个扩展字素簇的帖子摘要。
- 摘要超过 120 个扩展字素簇时带省略号。
- 卡片摘要最多显示 5 行，超出使用省略号。
- 连续字符、长链接和无空格文本必须换行，不得撑破布局。
- 昵称单行省略。

### 6.4 分页与刷新

- 使用游标分页，不使用页码。
- 下拉刷新重新读取第一页。
- 上拉加载更多。
- 同一翻页序列不得重复返回同一帖子。

## 7. 帖子详情

### 7.1 标题

- 作者打开本人帖子时，标题为“我的情绪”。
- 非作者打开时，标题为“TA的情绪”。

### 7.2 展示内容

- 作者头像、昵称、发布时间
- 完整正文
- 情绪标签和情境标签快照
- 评论数
- 三类轻互动数量
- 作者专属浏览量
- 作者专属到期时间

非作者详情不返回 `expires_at` 和 `view_count`。

### 7.3 正文与评论展示

- 详情正文完整展示，不做摘要截断。
- 正文和评论保留用户换行，并对长字符安全换行。
- 评论正文完整展示。

### 7.4 浏览量

- 只有作者详情可返回浏览量。
- 作者本人访问不增加浏览量。
- 非作者进入新详情页时，使用 `X-View-Token` 去重。
- 同一详情页刷新、回到前台或返回已打开页面时复用同一访问标识。
- 广场、详情非作者响应和“我的帖子”列表均不返回浏览量。

### 7.5 作者操作

作者可：

- 编辑有效帖子
- 删除有效、到期或下架帖子

已删除帖子不在详情和“我的”中展示。

### 7.6 非作者操作

非作者可：

- 发表评论
- 发送、切换或取消轻互动
- 举报帖子或评论

不能举报自己的内容。

### 7.7 不可用内容

非作者访问到期、隐藏、删除或不存在的帖子时，统一返回“内容已不可用”，不得泄露具体状态。

## 8. 发布帖子

### 8.1 编辑优先

- 游客可以先编辑正文、标签、留存时长和公开属性确认。
- 只有点击发布时才触发登录。
- 取消登录返回发布页，草稿仍保存在本机。
- 草稿在本机最多保留 24 小时。

### 8.2 正文

- 纯文字。
- 去除首尾空白后必须为 1 至 500 个 Unicode 扩展字素簇。
- 空正文和 501 个扩展字素簇均阻止提交。
- 不静默截断。

### 8.3 标签

- 标签由服务端配置。
- 情绪标签最多选择一个。
- 情境标签最多选择一个。
- 客户端通过公开的 `GET /tags` 获取启用标签。
- 服务端发布时重新校验标签存在、分类正确且仍启用。
- 帖子保存标签 ID 和名称快照。

### 8.4 留存时长

- 只允许 24、72、168 小时。
- 客户端默认预选 168 小时。
- API 必须显式提交 `retention_hours`，服务端不隐式补默认值。
- `published_at` 和 `expires_at` 在发布成功时固定。
- 编辑和访问不延长 `expires_at`。

### 8.5 公开属性确认

发布前必须确认：

- 内容会进入公共广场；
- 可能被其他用户查看或截图；
- 不应填写可识别个人身份的信息。

### 8.6 内容规则

服务端规则引擎返回三种结果：

| 结果 | 行为 |
| --- | --- |
| `PASS` | 正常发布 |
| `CONFIRM` | 需要用户确认风险提示，首次请求不落库 |
| `BLOCK` | 明确阻断，不创建帖子、不消耗成功配额 |

风险确认采用两阶段：

1. 首次命中未确认：返回 `JIJU_MODERATION_4092`、`challenge_id`、提示版本和求助资源，不创建帖子。
2. 用户确认后：携带 `challenge_id` 和 `risk_acknowledged=true` 重试。

规则配置外置，不在业务代码中硬编码真实词表和阈值。

### 8.7 配额

- 每个账号每个北京时间自然日最多成功发布 5 篇。
- 第 6 篇返回 `JIJU_QUOTA_4291`。
- 失败请求不消耗成功配额。
- 删除帖子不返还配额。

### 8.8 幂等

- 发布必须携带 `Idempotency-Key`。
- 格式为 `v1:post.publish:<uuid_v7>`。
- 重复点击和网络重试不得生成重复帖子。
- 同一幂等键对应不同载荷时返回冲突。

### 8.9 发布成功

- 返回帖子 ID、内容版本、公开状态、审核状态、发布时间、到期时间。
- 清理本地草稿。
- 进入帖子详情作者视图。

## 9. 编辑帖子

- 只有作者可以编辑。
- 只允许编辑有效公开帖子。
- 请求必须携带 `expected_content_version`。
- 成功编辑生成新内容版本，递增 `current_content_version`。
- 正文、标签重新校验。
- 高风险编辑重新进入 `PENDING` 审核。
- 不改变帖子 ID、作者、`published_at` 和 `expires_at`。
- 校验失败、版本冲突或版本已变化时，不覆盖当前公开版本。
- 编辑使用独立幂等键 `post.edit`。

## 10. 删除帖子

- 只有作者可以删除。
- 有效、到期和下架帖子可以删除。
- 删除后公开状态为 `DELETED`，写入删除时间。
- 立即从广场、详情和“我的”移除。
- 不返还发帖配额。
- 删除使用独立幂等键 `post.delete`。

## 11. 评论

### 11.1 列表

- 游客可读取有效帖子的评论。
- 评论按发布时间正序分页。
- 评论不返回浏览量、浏览者身份或后台审核信息。
- 登录用户可获得服务端计算的 `can_delete`。

### 11.2 发布

- 只有登录用户可评论。
- 评论正文去除首尾空白后必须为 1 至 200 个 Unicode 扩展字素簇。
- 目标帖子必须有效公开。
- 必须确认当前使用须知。
- 同一账号连续 60 分钟最多成功评论 10 条。
- 第 11 条返回 `JIJU_QUOTA_4292`。
- 评论使用幂等键 `comment.publish`。

### 11.3 删除

- 只有评论作者可以删除。
- 删除后评论不可见，评论数同步减少。
- 删除评论不回退其他业务配额。
- 删除使用幂等键 `comment.delete`。

## 12. 轻互动

### 12.1 类型

| 枚举 | 界面表达 |
| --- | --- |
| `HUG` | 抱一抱 |
| `HEAD_PAT` | 摸摸头 |
| `CHEER` | 握拳 |

三类互动在界面上使用统一图标风格，并带动作特效，不只显示文字数字。

### 12.2 规则

- 只有登录用户可互动。
- 目标帖子必须有效公开。
- 必须确认当前使用须知。
- 同一用户与同一帖子最多保留一条 `Reaction` 记录。
- 首次发送增加对应计数和总数。
- 切换类型时原类型减一、新类型加一、总数不变。
- 取消后当前互动为空，对应计数递减且不为负。
- 重复取消保持幂等。
- 数据库必须存在 `(user_id, post_id)` 唯一约束。

### 12.3 幂等

- 发送/切换：`v1:reaction.set:<uuid_v7>`
- 取消：`v1:reaction.cancel:<uuid_v7>`

## 13. 举报

### 13.1 可举报对象

- 有效帖子
- 有效评论

### 13.2 举报原因

| 枚举 | 展示名称 |
| --- | --- |
| `ABUSE` | 辱骂与骚扰 |
| `PRIVACY` | 隐私 |
| `DANGEROUS_OR_INAPPROPRIATE` | 危险内容 |
| `SPAM` | 垃圾信息 |
| `OTHER` | 其他 |

选择“其他”时必须填写说明。

### 13.3 规则

- 只有登录用户可举报。
- 必须确认当前使用须知。
- 不能举报自己的帖子或评论。
- 同一举报人、同一对象、同一原因在 24 小时内去重。
- 举报保存被举报对象的 `content_version`。
- 举报提交使用幂等键 `report.submit`。
- 普通用户只收到举报回执，不看到处理人员、处理原因或内部优先级。

## 14. 我的

### 14.1 游客态

- 展示登录提示。
- 只提供“微信登录”。
- 不提供“先去写一条”等误导性快捷入口。

### 14.2 登录态

个人中心展示：

- 系统头像
- 昵称
- 编辑入口
- 内容统计：全部、有效、已到期、已下架
- 内容管理：我的帖子、发布新内容
- 账号：个人资料、账号设置

菜单项只显示操作名称，不显示解释性副标题。

### 14.3 我的帖子

- 支持有效、已到期、已下架筛选。
- 仅查询当前账号。
- 展示正文摘要、标签、状态、时间、评论数和互动数。
- 已删除帖子不展示。
- 有效帖子提供编辑和删除入口。
- 到期和已下架内容只读。

## 15. 个人资料

个人资料按非社交匿名身份设计：

- 系统生成圆形头像，显示昵称首字。
- 不读取微信头像。
- 不支持头像上传。
- 不支持头像配色选择。
- 不提供个人简介。
- 仅允许修改昵称。
- 昵称长度为 1 至 20 个可见字符。
- 昵称输入框必须有固定高度、深色文字和清晰光标。

## 16. 账号设置

账号设置分为：

- 账号：当前昵称、登录状态
- 服务与协议：使用须知及确认状态
- 会话：退出登录
- 危险操作：永久注销账号

退出登录后回到广场首页。

永久注销进入 30 天冷静期；冷静期和清理策略仍必须由隐私、法务和数据保留规则最终批准。

## 17. 使用须知

使用须知至少说明：

- 内容进入公共广场，可能被查看或截图；
- 不应发布可识别个人身份、骚扰、仇恨或危险内容；
- JIJU 不提供心理咨询、诊断、治疗或危机干预；
- 用户可以删除帖子，到期内容停止公开回应。

确认记录按用户和须知版本唯一保存。

## 18. 运营管理后台

## 18.1 登录与会话

- 使用用户名和密码登录。
- 错误用户名或密码统一提示“账号或密码错误”。
- 登录后分配 8 小时后台会话。
- 后台令牌保存在当前浏览器标签页的 `sessionStorage`。
- 刷新页面保持登录。
- 关闭标签页或退出登录后清除会话。
- 后台密码不以明文保存或回填。

### 18.2 布局

- 左侧固定导航。
- 顶部栏显示当前页面和运营人员。
- 顶部工作区标签页支持打开、切换和关闭。
- 主功能页和处理页都以标签页形式打开。
- 数据工作台为固定首页标签。
- 每个处理页通过标签右侧关闭按钮关闭，不使用“返回列表”按钮。

### 18.3 导航

- 数据工作台
- 内容治理
- 待复核内容
- 举报管理
- 用户管理
- 审计日志

### 18.4 数据工作台

展示三项统计：

- 广场可见帖子
- 待处理举报
- 待复核内容

统一队列按入队时间、来源稳定顺序和记录 ID 分页，不提供独立优先级筛选。

### 18.5 举报管理

- 支持按处理状态和举报原因筛选。
- 原因使用简短分类。
- 每一行展示来源、原因、内容类型、状态、时间和处理入口。
- 点击处理打开独立内容处理标签。
- 不直接显示内部对象 ID。
- 举报原因统一为辱骂/攻击/骚扰、隐私、危险或不适当内容、广告或垃圾信息、其他。

### 18.6 待复核内容

统一展示：

- 用户举报
- 内容规则产生的待复核事项

来源列明确区分“用户举报”和“规则复核”。

“待复核”含义：

- 规则引擎无法直接给出最终结论；
- 需要运营人员按业务规则作人工判断；
- 不代表系统已经自动判定违规。

### 18.7 内容治理

- 支持帖子、评论类型筛选。
- 支持全部、公开中、待复核、已隐藏/违规、已到期、已删除状态筛选。
- 支持按内容摘要或作者昵称搜索。
- 使用游标分页。
- 到期帖子即使数据库公开状态仍为 `PUBLISHED`，后台也必须结合 `expires_at` 显示“已到期”。
- 列表只展示业务字段，不展示内部 `pst_...`、`cmt_...` 编号。
- 版本属于内部治理字段，不应成为普通列表的主要信息。

### 18.8 内容处理页

从举报、待复核或内容列表进入，作为后台工作标签打开。

包含标签：

- 概览
- 处理
- 记录

概览展示内容类型、作者、公开状态、审核状态、来源、举报原因、举报数、时间信息等。

处理规则：

- 普通内容复核可执行通过或违规判定。
- 驳回当前内容时立即隐藏。
- 内容可执行隐藏、下架或满足条件时恢复。
- 恢复不延长 `expires_at`。
- 已删除或旧版本的举报按举报保存的内容版本结案，不修改当前新版本或已删除内容。
- 举报来源不展示不适用的“内容状态”操作，只使用“内容复核”通过或驳回。
- 已处理事项显示“已处理”并停止重复提交。

记录标签展示该对象的审计记录。

### 18.9 账号处置页

从用户列表进入，作为后台工作标签打开。

包含：

- 概览
- 处理

可执行：

- 警告
- 限制发帖
- 限制评论
- 限制互动
- 封禁账号

限制类动作必须填写未来结束时间。封禁不删除用户内容。

### 18.10 用户管理

- 支持昵称搜索。
- 支持正常、受限、封禁、注销冷静期、已注销筛选。
- 展示系统头像、昵称、账号状态、帖子数、回应数、当前限制和加入时间。
- 点击处理进入独立账号处理标签。
- 可见页面不显示内部用户编号。

### 18.11 审计日志

- 只读。
- 支持按操作类型、对象类型和时间筛选。
- 展示动作、操作人角色、对象类型、版本、原因和时间。
- 不展示内部日志 ID 或对象 ID。

### 18.12 后台反馈

所有处理结果使用弹窗反馈：

- 成功
- 失败
- 数据失效
- 记录加载失败

已处理事项重复提交时提示“该事项已完成处理，无需重复提交”。

### 18.13 正式产品文案

后台界面不展示：

- 内部流程建议；
- 数据库表名或角色实现类名；
- 浏览器存储实现说明；
- `JIJU_*` 技术错误码；
- 内部对象 ID；
- “请从上方列表选择”等开发式操作说明。

## 19. 状态与生命周期

### 19.1 帖子公开状态

| 状态 | 含义 |
| --- | --- |
| `PUBLISHED` | 已发布；仍需结合审核和到期判断 |
| `HIDDEN` | 已隐藏或下架 |
| `EXPIRED` | 已到期 |
| `DELETED` | 已删除 |

`DRAFT` 仅存在客户端。

### 19.2 审核状态

| 状态 | 含义 |
| --- | --- |
| `PASSED` | 审核通过 |
| `PENDING` | 等待人工复核 |
| `REJECTED` | 判定违规 |

### 19.3 有效公开判断

帖子有效公开需同时满足：

- 公开状态为 `PUBLISHED`；
- 当前服务端时间早于 `expires_at`；
- 未隐藏、未删除；
- 审核状态为 `PASSED`；
- 或审核状态为 `PENDING` 且已完成风险确认。

### 19.4 到期

- 到期后从广场移除。
- 非作者详情、评论新增和轻互动均不可用。
- 作者可在“我的—已到期”查看只读历史。
- 到期不可恢复为公开。

### 19.5 版本

- 每次成功编辑生成新的不可变内容版本。
- 当前展示版本由 `current_content_version` 指向。
- 举报保存被举报时的内容版本。
- 审核记录保存处理的内容版本。
- 版本用于审计、历史核查和并发控制，不是独立帖子。

## 21. 错误与隐私规则

### 21.1 错误响应

统一包含：

- `code`
- `message`
- `request_id`
- 可选字段级 `details`

错误响应不得包含堆栈、SQL、内部主机、审核规则、浏览量、浏览者身份或内容存在性差异。

### 21.2 必须区分的错误

- 未登录
- 登录失效
- 权限不足
- 内容不可用
- 内容校验失败
- 发帖配额满
- 评论配额满
- 网络失败
- 状态冲突
- 版本冲突
- 风险确认要求

### 21.3 日志和埋点

不得记录：

- 帖子正文
- 评论正文
- 举报说明
- openid、unionid、session_key
- 手机号、证件号
- 会话令牌
- 浏览者身份

允许使用 `request_id` 和经过白名单定义的事件属性。

## 22. 数据实体

当前核心实体：

- `User`
- `AuthSession`
- `AdminCredential`
- `AdminRoleAssignment`
- `NoticeConfirmation`
- `Tag`
- `Post`
- `PostVersion`
- `Comment`
- `Reaction`
- `Report`
- `ModerationRecord`
- `AuditLog`
- `ViewRecord`
- `QuotaUsage`
- `IdempotencyRecord`

关键约束：

- 用户只有一个昵称，无个人简介和头像配色字段。
- `Reaction` 对 `(user_id, post_id)` 唯一。
- `Report` 必须保存目标类型、目标 ID 和内容版本。
- `Report` 与 `ModerationRecord` 分表。
- `Post.public_status` 与 `Post.moderation_status` 分离。
- 每个用户与每个须知版本唯一确认一次。
- `(post_id, version_number)` 唯一。
- `ViewRecord` 对 `(post_id, view_token)` 唯一。
- 幂等记录对 `(actor_id, operation, idempotency_key)` 唯一。

## 25. 非功能要求

### 25.1 安全

- 所有权限在服务端校验。
- 后台会话与普通用户会话隔离。
- 密码只保存哈希。
- 不记录敏感正文和身份凭证。
- 非作者内容不可用场景不得泄露存在性。

### 25.2 一致性

- 写操作使用事务。
- 配额消费和业务写入同事务完成。
- 轻互动使用数据库唯一约束和串行化事务。
- 举报去重和幂等并发安全。
- 编辑和审核使用内容版本控制。

### 25.3 UI

- 所有按钮组使用弹性布局，避免窄屏和长文案重叠。
- 所有长文本安全换行或按明确行数省略。
- 输入框文字、光标、状态标签和提示弹窗必须清晰可见。
- 页面不得出现过度的实现说明或开发提示。

### 25.4 性能

目标基线沿用 AC-24：

- 广场首屏和详情服务端 P95 不超过 1 秒。
- 发布、评论和互动服务端 P95 不超过 1.5 秒。
- 压测峰值至少覆盖预期峰值 2 倍。

当前是否有正式压测报告仍需发布前确认。

## 26. 明确禁止

- 不得新增未批准接口或字段。
- 不得在客户端决定权限、审核状态或公开状态。
- 不得把个人资料扩展为社交主页。
- 不得提供关注、粉丝、私信、匹配或用户搜索社交功能。
- 不得记录正文、评论、举报说明、微信标识或请求令牌到日志和埋点。
- 不得自行确定数据保留期限或求助资源内容。
- 不得把 mock 微信登录用于生产。
- 不得把后台技术错误码、数据库表名、内部 ID 或实现说明展示给普通运营人员。
- 不得在内容已删除后尝试恢复当前内容；举报应按其保存版本结案。
