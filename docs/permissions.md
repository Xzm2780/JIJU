# JIJU 权限矩阵

## 1. 范围与角色

本文依据 `docs/product/PRD-v1.1.md` 第 5.1 节“权限矩阵”、第 5.9 节“用户可见错误”和第 8 节“功能需求”整理。权限以服务端校验结果为准，客户端隐藏或禁用控件只用于改善交互，不构成授权。

角色按“当前操作对象”判断：

| 角色代码 | 角色 | 定义 |
| --- | --- | --- |
| GUEST | 游客 | 没有有效登录态。 |
| AUTH_NON_AUTHOR | 登录非作者 | 有有效登录态，但不是当前目标内容的作者；对于创建内容等无既有对象的操作，表示普通登录用户。 |
| AUTHOR | 作者 | 有有效登录态，且是当前目标内容或评论的所有者。 |
| OPERATOR | 运营 | 具备独立后台身份和相应角色权限。执行普通用户端操作时仍须以普通账号规则处理，后台角色不得绕过前台限制。 |

角色可以重叠。例如运营人员同时是帖子作者时，前台操作按 AUTHOR 规则处理；后台治理操作必须按 OPERATOR 规则重新鉴权。

## 2. 服务端校验点

矩阵中的每个角色格都标注了至少一个服务端校验点。校验点顺序不作为实现依赖；服务端应选择不会泄露对象存在性的安全顺序，并在必要时合并查询。

| 编号 | 服务端校验点 | 说明 |
| --- | --- | --- |
| S1 | 身份认证 | 校验登录态、令牌有效性和账号标识；区分未登录与登录失效。 |
| S2 | 账号状态与限制 | 校验账号是否被封禁，或是否被限制发帖、评论、互动。 |
| S3 | 后台角色授权 | 校验独立后台身份、角色、资源范围和动作权限。不得使用普通用户端会话替代。 |
| S4 | 对象归属 | 校验当前用户是否为帖子、评论、举报或目标资源的作者/所有者。 |
| S5 | 内容状态与可见性 | 校验目标存在性、到期、隐藏、删除、审核状态及操作是否适用；非作者不可用场景统一处理。 |
| S6 | 使用须知 | 校验当前协议版本是否已由用户确认；首次表达或互动前必须完成。 |
| S7 | 配额与频控 | 校验发帖自然日配额、评论连续 60 分钟配额及服务端防滥用限流。 |
| S8 | 内容校验 | 服务端校验正文、评论、标签、举报原因和举报说明等输入。 |
| S9 | 幂等与并发 | 校验请求幂等键、当前内容版本和状态版本，防止重复写入或覆盖并发更新。 |
| S10 | 响应字段裁剪 | 按角色白名单序列化响应，移除无权字段，尤其是浏览量和参与者身份。 |
| S11 | 审计留痕 | 记录后台操作人员、角色、时间、原因、动作及变更前后状态。 |

## 5. 服务端执行顺序要求

1. 先执行 S1 身份认证，再决定是否解析或查询业务对象。未登录请求不得先通过对象 ID 查询判断对象是否存在。（依据：5.1）
2. 登录用户访问非本人对象时，先执行 S4 对象归属和 S5 可见性判断，再生成业务响应；不得仅依赖客户端传入的角色或作者标记。（依据：5.1、5.9）
3. 发布、评论、轻互动和举报必须在服务端校验 S6 使用须知、S7 配额和 S9 幂等；失败请求不得消耗成功配额或生成重复数据。（依据：AUTH-03、POST-09、POST-11、COMMENT-07、COMMENT-09、REPORT-05）
4. 内容校验以 S8 的服务端结果为准；客户端校验只用于减少无效请求。（依据：POST-06、COMMENT-04）
5. 后台操作必须独立执行 S3 和 S11，不得复用普通用户端的只读权限；所有治理动作记录处理人员、时间、原因和状态变化。（依据：MOD-06、MOD-08、MOD-09）
6. 序列化响应时最后执行 S10；浏览量、浏览者身份、后台字段和非当前账号数据必须在输出前移除。（依据：DETAIL-04、VIEW-02、VIEW-03、MINE-06）

## 6. 特别安全检查

### 6.1 非作者访问不可见内容

对于游客和不具备作者身份的登录用户，以下情况必须返回完全相同的 HTTP 状态、错误码、用户可见文案和响应结构：

- 帖子已到期。
- 帖子已隐藏或下架。
- 帖子已删除。
- 帖子 ID 不存在或格式合法但无法定位。
- 不得返回不同文案以暗示“到期”“隐藏”“删除”或“存在但无权”。

统一使用 `JIJU_CONTENT_4041`，用户可见文案为“内容已不可用”。作者通过作者专属视图查看自己的到期或已下架内容时，可以按产品定义看到相应状态；已删除内容仍统一不可用。运营人员只能通过已授权后台和审计流程查看治理所需内容版本。

### 6.2 浏览量越权与存在性保护

- 广场信息流和普通详情响应不得包含 `view_count` 字段；不能依赖前端删除字段。
- 游客请求浏览量时先返回 `JIJU_AUTH_4011`，不得先查询帖子是否存在。
- 已登录非作者请求浏览量时统一返回 `JIJU_ACCESS_4031`，对存在、已到期、已隐藏、已删除和不存在的合法 ID 使用相同响应，不得泄露对象存在性。
- 作者只能查看本人有效或作者历史视图允许展示的帖子浏览量；作者本人访问不增加浏览量。
- 运营人员只能在独立后台、具备审计权限且确有必要时查看浏览量；不得返回浏览者身份或名单。

### 6.3 错误文案隔离

- 未登录、登录失效、权限不足、内容不可用、内容校验失败、配额满和网络失败必须使用 [errors.md](errors.md) 中彼此独立的错误码和用户可见文案。
- 权限错误不得伪装成内容不存在；内容不可用也不得伪装成登录失效。
- 所有错误响应可附带服务端 `request_id`，但不得包含目标作者、审核状态、隐藏原因、浏览量或其他无权数据。

## 7. 最小验收测试

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AUTHZ-01 | 游客直接调用发布、评论、互动、举报和“我的”接口 | 服务端拒绝，返回未登录错误，不产生数据。 |
| AUTHZ-02 | 登录非作者直接按 ID 调用编辑、删除和浏览量接口 | 服务端在响应层裁剪数据；编辑/删除拒绝，浏览量返回统一的权限错误，不泄露对象存在性。 |
| AUTHZ-03 | 非作者分别访问不存在、到期、隐藏和删除的帖子详情 | 四类响应的状态码、错误码和文案完全一致，均为“内容已不可用”。 |
| AUTHZ-04 | 作者访问自己的有效、到期和已下架帖子 | 按作者视图返回允许内容；已删除帖子仍返回“内容已不可用”。 |
| AUTHZ-05 | 普通用户绕过客户端直接调用后台治理或配置接口 | 服务端返回权限错误，不执行动作，不生成治理审计以外的敏感输出。 |
| AUTHZ-06 | 运营账号在普通前台发布、评论、互动或举报 | 按普通账号的登录、须知、配额、内容校验和幂等规则处理，不使用后台权限绕过。 |
| AUTHZ-07 | 检查广场、详情、“我的”和举报响应 | 所有非作者响应均不含浏览量、浏览者身份和非当前账号数据。 |
